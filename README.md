# 广告数据工作台

Windows 离线 HTML 工具。下载 ZIP、解压，用 Edge 或 Chrome 双击打开“广告数据工作台.html”。不需要安装 Python 或 Excel，无需联网，文件仅在本机浏览器中处理。上传搜索 ZIP／CSV 和两个周期效果表后，一次生成可下载的过程 Excel 与诊断 HTML，不需要再次上传过程表。

## 使用

1. 搜索数据区域拖入或点选一个 ZIP（内含 CSV 分片）或一个 CSV。
2. 对比周期区域选择前一个14天周期的效果 Excel。
3. 现期区域选择后一个14天周期的效果 Excel。
4. 点击“生成诊断报告”。当效果表包含多个采销时，弹出复选框：根据搜索商品匹配情况推荐勾选，用户可改选、多选。至少勾选一人。
5. 点击“按所选采销生成”，页面直接显示诊断报告。可以下载过程 Excel、新窗口查看报告，或下载独立 HTML 报告；报告可搜索、筛选、展开商品依据，并打印为PDF。下载文件保存至浏览器下载目录，或由浏览器询问位置。

三个输入由区域确定用途，不根据文件名猜测顺序。更换文件、重新生成或取消后，旧下载结果会清除。处理过程中可停止。

## SKU → SPU 识别与采销范围

效果表有两组同名“商品ID”“商品名称”时，按用户规定：左侧ID/名称属于SPU，右侧ID/名称属于SKU。通过同名列出现的先后顺序识别，不依赖绝对列号。其他字段均按列名读取，重复商品列不会报错。也支持显式命名的“SPU ID”“SKU ID”。

- 搜索CSV含SPU ID时，直接按SPU汇总。
- 搜索CSV只有“智能投放推广SKU ID”或“SKU ID”时，联合两个效果周期建立SKU→SPU映射，再汇总同一SPU下的搜索记录。
- 全组效果数据先按选中的采销筛选，再按SPU累计指标；搜索中明确属于未选采销的商品会排除并提示。
- 同一SPU下不同SKU正常累加。完全相同的效果明细整行去重；同一SKU的内容不同的记录保留并累加。两个周期分开处理，不跨周期去重。
- 没有映射或映射不唯一的SKU，以“未匹配SKU:编号”单独保留搜索指标，全量/推荐留空，提示中列出编号；不按名称猜测SPU。其归属无法确认，故不按采销过滤。这样数据不会丢失，但不意味着已完整匹配。
- 没有采销列时无需选择；只有一位采销时自动使用；多位时必须通过弹窗确认。推荐选择只作辅助，不等同于自动断定未匹配SKU的归属。

## 周期限制

读取效果表第一张sheet的“时间”，按包含起止日计算天数。两个效果周期须各14天、按前后顺序连续且不重叠；搜索“日期”须覆盖这两个周期（28天）。不符合时强制弹窗并阻止导出，不做天数折算。

本次文件：对比周期2026-10-03至10-16；现期2026-10-17至10-30；搜索覆盖10-03至10-30，全部符合要求。最初13天附件仅经用户授权用于独立计算验证，正式界面始终执行14天校验。

## Excel 输出格式

恰好三个sheet：

1. **广告搜索&推荐数据**：维持手工样例的27列，SPU_ID、商品名称、三级类目，以及搜索/推荐/全量各8项指标（曝光、点击、CTR、CVR、GMV、订单、CPC、ROI）。按搜索曝光降序，保留所选采销全部SPU及未匹配SKU。
2. **广告成交数据（对比周期）**：该文件第二张sheet中所选采销的明细，去除完全相同整行后，保留原列名、原列顺序及左右两组商品列。百分比文本转为Excel百分比数值。
3. **广告成交数据（现期）**：同上。

源效果表原有多少列就保留多少列，本次是40列，旧样例是37列。不会用旧样例固定列位置读取新数据。首张sheet中的ID为文本；A1批注记录周期、采销范围及处理异常。

搜索曝光、点击、GMV、订单、花费来自“展现数、点击数、直接订单金额、直接订单行、花费”。全量对应两个周期所选采销的“展现、点击、成交金额、成交父单量、消耗”相加。推荐=全量−搜索。

CTR=点击/曝光；CVR=订单/点击；CPC=花费/点击；ROI=GMV/花费。先累计再计算，比率保留4位小数，GMV保留2位。分母为零或负数则比率留空，负差额原值保留并提示。效果表成交父单量与搜索直接订单行、消耗与花费可能存在业务口径差异，需要结合源报表解释推荐差额。

## 商品诊断规则

诊断直接读取本次生成的三张过程Sheet，按Sheet名称、字段名及类型识别数据；以SPU为主键取三表并集，一条有效SPU只对应一条诊断。无法定位SPU的“未匹配SKU”等记录从诊断剔除并披露，过程表继续保留这些记录。名称缺失时按同一SPU从成交表补齐。

前14天、近14天GMV分别来自两张成交表的“成交金额”，近28天为两者之和，不使用搜索Sheet GMV代替。现期无记录时近14天GMV按0并明确标注，不推断下架或不可售；前期无记录也按0并披露。存在记录但成交金额整组为空时，保持未知，不冒充0。SKU级已提供数值按SPU加总，部分单元格为空时仅累计已提供值并披露。

1. 近14天GMV高于前14天为增长，备注“不需要调”；持平和下降均为不增长，备注“需调整”。前期0、现期正数为增长，增长率留空。
2. 增长商品停投状态固定为“不适用：GMV增长，仅提供建议”，停投原因为空，继续接受后续优化和ROI／预算检查。
3. 仅不增长商品执行停投：近14天GMV为0；否则近28天GMV低于200且现期投后毛利为负。两项同时命中优先归类为现期GMV为0。其他不增长商品为“未命中停投条件”；必要字段不足时明确待补充。
4. 未停投商品全量CTR／CVR低于对应三级类目简单均值时，先优化承接。CTR低则优化主图、白底图、标题、短标、价格、活动；CVR低则优化商详、价格、好评；同时偏低则并行。等于均值不算低。均值包含全部有效商品，不按流量加权，也不因增长或停投状态排除样本。
5. 未停投且无需优化承接时，推荐点击占比≥70%：不亏损则拉高ROI＋拉高预算，亏损则拉高ROI＋降低预算；占比<70%则调低ROI＋维稳预算。全量点击为0时占比按0并披露。其他必要数据缺失时归入“数据待补充”，不强行给出结论。

动作分组互斥，优先级：停投＞先优化承接＞ROI／预算调整。缺失指标不填0；源报表没有搜索维度记录的商品，在过程表中将搜索／推荐／全量指标留空，诊断GMV和毛利仍来自成交表。CTR/CVR为负时原值保留在依据里，但不作为有效比较指标；非负数值按原值参与均值与比较。

展现位适配三条件为AND，包含等号：搜索CVR≥推荐CVR×1.5、搜索CTR≥2%、搜索CTR≥推荐CTR×1.2。完整但不满足判为“非搜索主导”，缺失判为“待补充”。搜索主导且用户确认有大词时为“重点搜索主导”。

### 本阶段确认的口径设置

界面提供两个可取消的设置，默认遵循本次用户确认：

- “预估投后履约毛利”可作为“京喜预估投后履约毛利_折后”的同口径别名。优先使用指定原字段，仅缺失时使用已确认别名；取消设置后不替代。现期毛利<0判亏损，≥0不亏损；前期毛利只作趋势展示。
- 本阶段所有三级类目均按有搜索大词处理。本次有效商品涉及4个类目；报告明确此前提来自用户确认，不声称已从关键词验证。取消设置后大词前提标待确认。

报告提供动作/类目/增长状态筛选、商品搜索、每条SPU的判定依据、类目基准和样本数、剔除记录、输入文件、字段类型与行列数、数据质量统计。下载的HTML包含本次诊断数据，可独立离线打开。

环境中未提供file-data-agent技能，因此使用内置JavaScript规则引擎，并用独立Python实现核对真实附件结果。

## 构建

运行 `python3 build.py` 生成 `dist/广告数据工作台.html`；运行 `python3 package.py` 重新生成下载ZIP。用户运行成品不需要Python。

`core.js` 为解析、映射、筛选、汇总逻辑，`diagnosis.js` 为诊断规则，`report.js` 为独立HTML报告生成器，`index.template.html` 为界面，`research` 中包含真实附件回归测试和独立验证脚本（运行这些测试需要对应附件）。库随包提供：SheetJS Community Edition 0.18.5（Apache-2.0）、fflate 0.8.2（MIT）。
