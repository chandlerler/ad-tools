## 下载

- [附件13天验证结果 Excel](https://github.com/chandlerler/ad-tools/raw/refs/heads/main/deliverables/广告分析_附件13天验证结果.xlsx)
- [源代码打包](https://github.com/chandlerler/ad-tools/raw/refs/heads/main/deliverables/广告数据工作台_源代码.zip)

下载离线工具 ZIP 并解压，双击其中的 HTML 文件。若仓库为私有仓库，请先登录有访问权限的 GitHub 账号。

Windows 离线工具。解压后双击“广告数据工作台.html”，用 Microsoft Edge 或 Chrome 打开；不需要安装 Python、Excel 或连接网络。它是可在桌面直接打开的 HTML 工具，不是原生 EXE。

## 使用

1. 搜索区域：选择一个 ZIP（包含一个或多个 CSV）或一个 CSV。
2. 对比周期区域：选择前一个14天周期的效果 Excel。
3. 现期区域：选择后一个14天周期的效果 Excel。
4. 点击“生成 Excel”，检查提示，再点击“保存 Excel”。浏览器会使用下载目录，或按浏览器设置询问保存位置。

每个区域支持拖放或点选，顺序由区域决定，不根据文件名猜测。文件名只用于显示。执行时可点击“停止处理”。数据仅在浏览器本机内存中处理。

## 日期校验

效果表第一张 sheet 中的“时间”用于校验日期，第二张 sheet 用于读取数据。每个效果周期必须正好14天（首尾日期都包含），前后周期须连续、不重叠。搜索 CSV 的“日期”须覆盖这两个周期，即28天。非14天或日期不符时显示弹窗、阻止导出，不进行日均折算。

例如：对比周期10月1日—14日；现期10月15日—28日；搜索周期10月1日—28日。

本次附件两个周期各13天。经用户授权，仅在本次独立验证中按实际13天计算；正式软件不提供绕过限制的开关。

## 输出与计算口径

恰好三个 sheet：

- 广告搜索&推荐数据：所有输入SPU的并集，按搜索曝光降序。按列名读取，使用 CSV 自带的 SPU ID 将 SKU/关键词/地域等行累加。
- 广告成交数据（对比周期）：效果表第二张 sheet，保留数据列及其顺序，百分比文本转换为Excel数值百分比。
- 广告成交数据（现期）：同上。

搜索曝光、点击、GMV、订单、花费分别来自“展现数、点击数、直接订单金额、直接订单行、花费”。全量对应两张效果表的“展现、点击、成交金额、成交父单量、消耗”之和。推荐为全量减搜索。

CTR=点击/曝光；CVR=订单/点击；CPC=花费/点击；ROI=GMV/花费。先汇总再计算，不对比率简单平均。比率保留4位小数，GMV保留2位。分母不大于0时比率留空。负差额保留并提示，绝不静默改成0。第一张sheet的A1批注包含处理口径、周期和异常提示。

效果表成交父单量与搜索直接订单行的业务口径可能不同，消耗与搜索花费也可能存在折扣口径差异。因此推荐的订单、GMV、花费和相关比率需结合源报表口径解释。

名称/类目优先取现期效果表，其次对比周期；仍未匹配时回退到搜索报表。效果表两个周期都未匹配的SPU，全量和推荐留空。ID按文本处理。表头重复、必需字段缺失、效果表商品ID重复或无效数值时停止并提示。

ZIP支持多个CSV，逐分片解压；CSV支持UTF-8及GB18030。相同内容的多个分片仍会累加，请避免重复放入报表。

## 验证结果

附件：14个CSV、434694行、152个搜索SPU。152个SPU的搜索曝光、点击、直接成交金额、直接订单数均与手工表一致。全部输入并集为162个SPU。搜索曝光919991、点击48599、直接订单1419、直接成交金额69305.22。

按用户确认的“效果表全量减搜索”口径，55个SPU至少一项指标出现负差额。本次验证输出保留这些原值。手工样例采用了不同全量数据/CPC口径，程序不复制那些差异。

浏览器测试覆盖：三个文件区、拖放CSV、13天弹窗拦截、14天有效数据导出、效果表列顺序重排及三sheet下载。测试在Linux Chromium的本机HTTP环境执行；当前环境的浏览器策略禁止file地址，因此未实际验证Windows系统上的双击运行。

## 源代码与构建

core.js 为处理逻辑，index.template.html 为界面，vendor 为随包提供的固定版本库；运行 python3 build.py 可重新生成单文件HTML。Python只用于开发构建，最终用户无需安装。

第三方库：SheetJS Community Edition 0.18.5（Apache-2.0）；fflate 0.8.2（MIT）。运行过程中无外部依赖下载。

## 提示“缺少 SPU ID”时

搜索 CSV 必须包含 SPU ID 列。部分京准通导出只包含“智能投放推广SKU ID”，该字段是SKU编号，不能重命名为SPU ID来绕过校验。请检查导出字段是否支持加入 SPU ID；若该入口不提供此字段，需要补充可靠的 SKU→SPU 对照，并增加相应映射流程。当前版本不会按名称猜测映射，也不支持直接导入对照表。

2026-10-03 至 2026-10-30 的本次搜索ZIP包含两个CSV，两者均缺少SPU ID；对应两张效果表的日期满足14天要求。程序已改进报错，显示具体分片、检测到的SKU字段和处理建议。此类文件仍会停止处理，以免将SKU错误当作SPU输出。
